# 我的知识库

## 核心方法论

**PARA + 原子笔记 + 内容地图(MOC)** 混合模型:

| 方法 | 负责什么 |
|------|---------|
| PARA | 决定笔记"放哪"——按可执行性分类 |
| 原子笔记(Zettelkasten) | 决定笔记"怎么写"——一篇一事、用自己的话 |
| 内容地图(MOC) | 决定笔记"怎么找"——导航枢纽 |

## 五条铁律

1. **捕捉优先,整理靠后**——碎片先进收集箱,绝不在收集时整理
2. **原子化**——一篇笔记只讲一件事,标题即主题
3. **费曼式写作**——用自己的话写,复制粘贴的东西永远不会再读
4. **链接 > 文件夹**——靠 `[[双链]]` 和内容地图导航,文件夹只做大类分区
5. **定期回顾**——周清收集箱、月检内容地图,知识靠"复用"才活

## 目录说明

| 目录       | 用途         | 说明                    |
| -------- | ---------- | --------------------- |
| `00 收集箱` | 碎片收集       | 唯一允许"乱"的地方,每周清空       |
| `01 项目`  | 有明确目标+截止时间 | 如 `2026-08-知识库搭建`     |
| `02 领域`  | 长期维护的领域    | 正在学的技术、负责的系统          |
| `03 资源`  | 主题参考资料库    | 按主题建子目录,如 `03 资源/Go/` |
| `04 归档`  | 完成/过时内容    | 只进不出会乱                |
| `10 导航`  | 内容地图(MOC)  | 每个大主题一篇导航笔记           |
| `20 模板`  | 所有模板       | 新建笔记时复制使用             |

## 运转流程

```
捕捉 → 每周回顾 → 内化 → 检索复用

① 碎片随手进收集箱(1分钟,不整理)
② 每周分类:有目标→01 项目 / 长期领域→02 领域或03 资源 /
   重要知识点→写成原子笔记并挂到 10 导航 / 过时→04 归档或删除
③ 学习时写原子笔记,强制关联已有笔记
④ 通过内容地图导航 + 全文搜索检索,知识必须"输出"才有效(写作/代码/分享)
```

## 写作规范

- **命名**:标题即主题,简短清晰,如 `Go 泛型约束详解`
- **开头**:一段 1-2 句话的总结,方便快速回顾
- **正文**:小标题分段,多用例子和代码
- **关联**:与已有笔记建立 `[[双链]]`
- **结尾**:写清"下一步"要做什么
